# UPI Transaction Intelligence Platform

**Status: Core pipeline complete ✅ | Chat/voice layer + UI: not yet built**

## What is this?

A smart assistant that reads a user's UPI transaction history and turns
raw transaction data into three kinds of useful insight:

1. **Subscription tracking** — automatically finds recurring payments
   (subscriptions, EMIs, memberships) hiding in your transaction history,
   so you stop paying for things you forgot about.
2. **Fraud detection** — flags suspicious transactions (unusual amounts,
   odd hours, brand-new payees, rapid-fire payments) that look different
   from your normal spending behavior.
3. **Alternate credit scoring** — computes a fair credit-worthiness score
   from cash-flow patterns alone, for people who don't have a traditional
   credit history (gig workers, informal-sector earners).

The key architectural idea: **all three insights come from the same
underlying transaction data**, processed through one shared pipeline —
not three separate apps.

In plain terms: *"It's like having a smart financial friend who reads
your transaction history and warns you about wasted subscriptions,
catches suspicious payments before you lose money, and helps you get a
fair credit score — even if you've never had a credit card."*

## Current scope (honest boundaries)

This is a 3-day prototype. What's real vs. simulated:

| Piece | Status |
|---|---|
| Transaction data | **Synthetic** — generated locally, not real bank data. Structured to mimic what Account Aggregator (AA) data looks like. |
| Subscription detection | **Real logic** — rule-based interval/amount matching, works on any transaction data with this schema. |
| Fraud detection | **Real logic** — rule-based (amount spike, odd hour, new payee, velocity burst). Currently catches ~59% of injected test anomalies — documented honestly, not overtuned to the synthetic data. |
| Credit scoring | **Real logic**, but a v1 heuristic formula, not a trained ML model (no real labeled default/repayment data exists to train on). |
| Account Aggregator integration | **Not built** — real AA sandbox integration is out of scope for 3 days; this is future work. |
| Cross-bank dispute tracking | **Not built** — requires institutional/NPCI access, not achievable outside a real fintech partnership. Future work. |
| Chat/voice explainability (Groq) | **Not yet built** — planned next layer. |
| Dashboard UI (Streamlit) | **Not yet built** — planned next layer. |

```
    ├── generate_dataset.py    # synthetic UPI transaction generator
    ├── subscription_detector.py  # Module 1: recurring payment detection
    ├── fraud_detector.py      # Module 2: rule-based anomaly flagging
    ├── credit_score.py        # Module 3: alternate credit scoring

```

## How to run it

```bash
cd src
pip install -r ../requirements.txt --break-system-packages
python main.py
```

This will:
1. Generate a fresh synthetic dataset (~980 transactions, 12 users) into `data/upi_transactions.db`
2. Run subscription detection → populates `detected_subscriptions` table
3. Run fraud detection → populates `fraud_flags` table
4. Run credit scoring → populates `credit_scores` table

Safe to re-run any time — every step wipes and regenerates its own output.

To inspect results directly:
```bash
sqlite3 ../data/upi_transactions.db
sqlite> SELECT * FROM detected_subscriptions;
sqlite> SELECT * FROM fraud_flags;
sqlite> SELECT * FROM credit_scores;
```

## Verified results (last pipeline run)

- 979 synthetic transactions generated across 12 users
- 23 subscriptions detected (ground truth: ~24 injected — close match)
- 37 fraud flags raised (ground truth: 63 injected anomalies — ~59% recall, honestly reported)
- Credit scores computed for all 12 users, ranging ~650-834, correlating with but not identical to declared income (confirms the model is reading behavior, not just income level)
